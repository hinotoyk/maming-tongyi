## 名称档案表二次重构：九列 → 三列（2026-11-27 傍晚）

用户对「方案 A（七列双行格）」仍不满意，反馈「也好丑」。这次先跑数据再改版式，
结论是**问题不在留白，在信息密度**——表格近一半宽度在展示没有新信息的内容。

实测（28028 行，`public/data/search/rows.json`）：
- 英文栏 **78%** 与原文完全同值；简体栏是港译的繁→简转写（24% 连字都相同）
- **自译、简称 100% 为空**
- 状态栏 89% 是两个值（待维护/公告直取），只有 10.7% 是「已校订」
- 国籍空 23.4%，32 个 ISO 码
- 名称栏有效数分布：88.8% 的行只有 4 个（原文+英文+港译+简体）

改法（`src/pages/index.astro` + `global.css`，业务逻辑未动）：
1. **收回三列**：分类（类型+国籍码合一）/ 原文 / 港译。删掉自译、简称、状态三列。
2. **派生写法按需出现**：英文与原文同值时 `hidden` 不渲染，简体与港译同值时同理，
   不再用「—」占位——破折号污染是页面「脏」的主因。
3. **对照式对齐**：原文栏右对齐、港译栏从一道 1px 竖线起左对齐，借双语对照书的版式，
   竖线即「翻译发生的位置」，中间不再隔一段无信息的空白。
4. **层级**：港译 16px/600/深青（主角）> 原文 12.5px/500/#565656 > 派生 10.5px/#b3b3b3 >
   分类 10.5px/#8a8a8a + 等宽国籍码 9.5px。
5. **索引栏**：分类列左边缘 3px 主色条，四种类型用透明度分档（马 .7 / 赛 .34 / 骑 .26 / 练 .48），
   类型+国籍码上下排，列右侧一道边线收口。
6. **状态**：只保留「已校订」的一枚 15px 圆勾，跟在港译名字后面（不另起一列）。
7. **节奏**：`td` 最小行高 40px；每 10 行行线加深一档（#ededed → #dedede）。
8. 行尾悬停才出现的小箭头，给行右边缘一个视觉终点。
9. `.wrap` 加 `max-width: 1180px` 居中，避免超宽屏把港译列拖出半屏空白。
10. 导语同步改写（原文描述的「九栏」已和实际表格不符），手机端统计行只留总数，首屏多放一条。

**已知取舍**：三列在 ≥1280px 时港译列右侧仍有 250–430px 空白。这是数据属性——
每条记录只有 3–4 个短字段，任何三列布局都会有。要彻底填满只能改呈现方式（双列瀑布/卡片网格），
但会牺牲「竖着扫港译列」的能力。试过双列（856px 分两栏 → 每列 428px），原文/港译列被挤到 159px
开始截断，已放弃。

**踩坑**：`table` 的 `width` 不吃 `min()`，`max-width` 在 `table-layout: fixed` 下也不可靠；
限宽要通过外层 `div`（`.card.names .tblwrap`）来做。390 视口截图要用 iframe 包一层，
直接 `--window-size=390` 会被 Edge 最小窗口宽撑开。

**交互**（`index.astro` 的 SSR + `rowHtml()`）：
- 原文仍是 `<a>`，悬停下划线只到字宽 + `↗`（`align-self:flex-end` 让链接收缩到字宽，
  否则 block 级 a 的 background 下划线会拉成整列宽）。
- 其余名字（英文/港译/简体/自译/简称）改成 `<button class="cp" data-copy data-l>`，

  悬停 = 8%→10% 主色浅底 + 一枚 ⧉；点击后按钮转主色 + 勾 900ms，底部浮 `已复制 · xxx` 1.5s。
- 事件委托到 `document`（翻页会重写 tbody）；`navigator.clipboard` 失败时退回
  textarea + `execCommand`；`prefers-reduced-motion` 里把这些新 transition 一并关掉。

**两个连环 bug（都是「元素宽度算错」）**：
1. `.cp::after` 图标平时占 12px 行内宽度 → 240px 港译列被挤掉半个字，名字无故带省略号。
   改成 `width:0` + 悬停才 `width:12px`。
2. 图标不占位后，`.ncell-hk` 也没撑满 → 按钮 `align-self:flex-start` 的可算宽度塌成几个字，
   省略号仍在。补 `.ncell-hk{flex:1 1 auto}`（移动端 `flex:1 1 0`）。
3. **手机端校订勾消失**的真凶是旧规则 `@media(max-width:640px){ .card table{min-width:620px} }`
   （为横向滚动留的），把整表撑到 620px，勾被推出视口。改成 `.card:not(.names)`。

**排查手法**（值得复用）：Edge headless 的 `--dump-dom` + 在同源 iframe 里跑脚本读
`getBoundingClientRect` / `getComputedStyle`，比反复截图猜快得多；注意 Edge 最小窗口宽约 500，
量 390 视口必须用 iframe。弹窗/提示这类要点击才出现的态，做一个只有静态 class 的样张页
（`/statecheck.html`）就能看。截图要用独立 `--user-data-dir`，否则会拿到缓存里的旧 CSS。

## 技术栈对比（yunji-web vs 本仓）· 已暂停，未改代码

用户质疑「为什么用 Astro 服务器，应该和 yunji-web 一致」。实测两边：

- yunji-web / kzn-web：Vite 5 + Tailwind 3 + 原生 JS，`front/pages/*.html` 12 个多页入口，
  数据 `dist/data/*.json`（12MB / 276 个逐马文件）运行期 fetch 客户端渲染；
  本地 `python serve.py`（9090，no-cache + CORS）；dist 8.7MB / 13 个 HTML；部署 GitHub Pages。
- 本仓：Astro 5.18（底座同为 Vite）+ Tailwind 4 `@theme`，5 个模板 × getStaticPaths，
  **28084 个 HTML**（马 21554 / 人 3643 / 赛 2883），构建期读 `public/data` 分片，
  页面不含 fetch；dist **494MB**，构建 4m22s（CI timeout 40min）。

根因：276 匹马 → 一份 JSON 全渲染；28028 条名字 → 一实体一 URL，不构建期出页就只能
hash 路由，长尾 SEO 归零。Astro 是首个代码提交 `10327c3`（11-26）就定的，AGENTS.md §3 有写。

**关键新发现**：GitHub Pages 1GB 硬顶已用一半；日本只占 235 条公告，其余 13 地区全 pending，
全量爬完必然撞线 → 这是页面数量策略问题，不是框架问题。

给出三选项：A 保持 Astro + 补 serve.py（9094，0.5h）／B 换 Vite 原生 MPA（2–3 天，不建议）／
C Astro 瘦身：只给 curated 3008 + races + persons 出页，pending 18494 收进可检索单页
（dist→约 120MB，构建 <1min）。用户选择「先暂停」，未动手。

排查手法补充：Astro dev 起在 4321，`npm run dev -- --host 127.0.0.1 --port 4321` 需后台跑，
首页路径带 base `/maming-tongyi/`，`curl -o /dev/null -w "%{http_code}"` 验 200 即可。
