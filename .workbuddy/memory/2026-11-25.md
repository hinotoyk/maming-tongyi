## 重大口径变更：一张表 = 一场（已写进 IMPL §16.2）

原实现「一篇公告 = 一场」，多表公告只取正赛一张。实测 183 篇 docx 有 **890 张名单表**，
单表公告只有 48 篇 → 丢 3/4 场次。用户确认改为**一张表 = 一场**：

- 正赛表沿用公告 uid（URL 稳定），副场用 `C.race_uid_sub()` = `{prefix}-{year}-{mmdd}-{slug}`；
- 同日同名（「三歲以上一捷馬賽」每周都有）用开跑时间后缀消歧，如 `-1145`；
- 跨公告同名 uid 在解析期加后缀，`dedupe_same_race()` 再按 (赛期,场次,途程,马场) 合并，
  优先保留**不带后缀且单表**的那份。

## 修掉的四个解析 bug（IMPL §16.3 有表）

1. **href 撇号截断**：`Prixdel'ArcdeTriompheDay_FinalDecl_OC_C.docx` 被 `[^"']+` 截断，
   整条附件链接静默丢弃 → 改为按定界符匹配 `href\s*=\s*(?:"([^"]*)"|'([^']*)')`，
   并清掉 href 里的换行（曾让 curl exit 3）。
2. **导航当表头**：内联表无信息行时上下文是整页导航，`parse_header` 把墨爾本盃解成 1650 米
   → `clean_info()` 拦截（含「所有新聞消息/選擇其他新聞」或 >240 字），全文兜底只对 docx/doc 做。
3. **暫定公告整篇无赛期**：改为同一份公告内 `race_date/venue/session` 互补，**途程不互补**。
4. **名称冲突静默丢**：同一匹马多个港译原先只打提示 → 现在写 `review_queue(kind='name')`（27 条）。

## 分页（15:40）

索引页与改名页原先只渲染首屏 200 行、其余「按关键词现查」，等于 28,386 条没有入口。改为每页 200 行：
SSR 出第 1 页，客户端在全量上切片。顺序只有一份——`s5_export.py` 按五队列加权轮转
（curated 马 3/其他马 2/赛事 1/骑手 1/练马师 1）写 rows.json，`lib/data.ts` 用同一 WEIGHTS 生成首屏；
校验过 `data-uid` 逐条相等、第 2 页与末页无缺口。改名页改为「curated 马→其他马→赛事→人物」拼接
（干活页不做交错），客户端同规则重排。

两个只有真点才暴露的坑：
- 首屏是 SSR，客户端 `view` 为空 → `ceil(0/200)=1`，第一次点「下一页」原地不动。`goto()` 先 `primeView()`。
- 改名页翻页重建 DOM 会丢未保存改动。改为草稿层 `drafts` + `base` 两个 Map，输入即入草稿，
  重绘回填、按 uid 比对出 patch。浏览器内实测：改名→第 2 页→回第 1 页，输入仍在、patch 只含该条。

验证：`?page=2` 200 行 201–400、`?page=143` 186 行、`?kind=trainer&page=2` 200 行 2/14、
`?q=Caffrey` 1 条；按钮 1→2→143→142 与 disabled 状态正确。`check_data` 11 通过 / 3 告警 / 0 失败。
