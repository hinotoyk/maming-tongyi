## v3.3 风控与自适应限速（`pipeline/netguard.py`）

用户要求把风控写进实现手册：实时监控有无风控、随时调整、跑完总结出合理间隔。

**新增 `pipeline/netguard.py`（已实现，可直接用）**
- 唯一出网口：`Guard.get()` / `Guard.download()`；curl 实现（项目无 requests 依赖）。
- 判定顺序：curl 退出码 → 状态码 → 正文特征 → 正文长度。outcome = ok/throttle/challenge/notfound/server/net/empty。
- 关键区分：HKJC 限速信号是 **400**（不是 429）；`empty`（200 但 html <600 字）= 隐性限速；
  **JBIS `/horse/{id}/` 的 503 是结构性的，特判为 server 不抬间隔**（`jbis-detail-503`）。
- 自适应 AIMD：风控 ×1.6 立刻生效，连续成功 20 次 ×0.9 回落，`max(floor, …)` 永不破地板；抖动只上不下。
- 熔断：连续 5/4/3 次（HKJC/JBIS/IA）→ `RiskControlStop` → 调用方 exit 2；状态落 `cache/http/state.json`，
  重跑从抬高值继续。`tune --host --interval` 可人工改（只能改慢）。
- 流水 `cache/http/journal.jsonl`（ts/host/status/latency/outcome/interval/attempts）。
- `report` → `cache/http/ratelimit-report.md`：稳定性判定（样本<50=样本不足）、建议间隔 =
  clamp(零风控且≥50样本的最小间隔档 ×1.25)、逐站延迟 p50/90/99、间隔档×风控率表。
- `selftest` 不联网验证 10 条判定 + 自适应数学 + 报告数学（2.0→8.2→2.3s，建议 4.5s），全绿。
